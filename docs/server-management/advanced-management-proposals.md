# 상업용 인프라 운영을 위한 고급 서버 관리 기능 제안서

이 제안서는 분산 워커 서버 인프라를 체계적이고 안전하게 관리하기 위해, 기존 기능(모니터링, systemd, 패키지 관리) 외에 추가적으로 도입이 권장되는 **5대 고급 서버 관리 기능(Advanced Server Management Features)**을 제시합니다.

---

## 1. 5대 고급 서버 관리 기능 제안

```
┌────────────────────────────────────────────────────────────────────────┐
│ [추천 1] 사용자 계정 및 SSH 키 중앙 통제                                  │
│ - authorized_keys 일괄 관리, 퇴사자 키 즉시 회수 및 백도어 방지         │
├────────────────────────────────────────────────────────────────────────┤
│ [추천 2] 네트워크 포트 및 호스트 방화벽(UFW) 관리                        │
│ - 화이트리스트 IP 설정, Fail2ban 침입 탐지 상태 중앙 감시                │
├────────────────────────────────────────────────────────────────────────┤
│ [추천 3] 설정 파일 감시 및 드리프트(Drift) 감지                         │
│ - sshd_config, hosts 등 중요 설정 무단 변경 탐지 및 무결성 검증          │
├────────────────────────────────────────────────────────────────────────┤
│ [추천 4] 분산 노드 간 네트워크 연결성 및 속도 진단                       │
│ - 워커 <-> 오케스트레이터, 워커 <-> 모델 API 간 레이턴시 및 속도 측정    │
├────────────────────────────────────────────────────────────────────────┤
│ [추천 5] 하드웨어 디바이스 진단 및 SMART 모니터링                       │
│ - smartctl 디스크 수명 예측, CPU/VRAM 온도 및 팬 센서 에러 선제 감지     │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. 기능별 세부 설계 및 기대 효과

### 2.1 사용자 계정 및 SSH 키 중앙 통제 (Identity & SSH Key Revocation)
* **기능**: 모든 워커 노드의 리눅스 시스템 계정 및 공용 접속을 위한 SSH 공개키 목록(`~/.ssh/authorized_keys`)을 오케스트레이터 대시보드에서 일괄 조회하고 관리합니다.
* **작동 메커니즘**:
  * 관리자가 대시보드에서 특정 직원의 SSH 키를 무효화(Revoke)하면, 오케스트레이터가 가입된 모든 워커에 명령을 발송하여 해당 키 라인을 삭제 처리합니다.
* **기대 효과**: 퇴사자 발생 시 수동으로 수십 대의 서버에 들어가 SSH 키를 빼는 번거로움을 제거하고, 보안 구멍(Backdoor)을 원천 차단합니다.

### 2.2 네트워크 포트 및 호스트 방화벽(UFW) 관리
* **기능**: 각 워커 노드 로컬 방화벽(`UFW` 또는 `firewalld`)의 정책 상태를 수집하고, 인바운드 허용 IP 대역을 원격으로 변경합니다.
* **작동 메커니즘**:
  * UFW 및 `iptables` 규칙을 파싱하여 대시보드에 시각화하고, 비정상 접속 IP를 차단하는 `Fail2ban` 감옥(Jail)에 갇힌 차단 IP 현황을 중앙에서 모니터링합니다.
* **기대 효과**: 보안 정책의 일관성을 유지하고, 외부 공격 시도를 단일 대시보드에서 통합 진단합니다.

### 2.3 설정 파일 무결성 감사 및 드리프트(Drift) 감지
* **기능**: 서버 보안 및 네트워크에 민감한 핵심 설정 파일들의 변경 여부를 주기적으로 체크(Drift Detection)합니다.
* **대상 파일**: `/etc/ssh/sshd_config`, `/etc/pam.d/common-auth`, `/etc/hosts`, `/etc/resolv.conf`
* **작동 메커니즘**:
  * 에이전트가 1시간 간격으로 대상 파일의 SHA-256 해시(Hash)를 계산하여 기록해 둡니다.
  * 해시가 변경된 경우(수동 편집 또는 비인가 조작), 오케스트레이터가 알림을 띄우고 이전 백업과의 차이점(diff)을 보여줍니다.
* **기대 효과**: 비인가자에 의한 서버 환경 훼손 및 설정 오류를 조기에 탐지하여 인프라 무결성을 증명합니다.

### 2.4 네트워크 레이턴시 및 경로 속도 진단
* **기능**: 워커에서 외부 모델 API(`api.z.ai` 등) 및 오케스트레이터 서버, 외부 GitHub 저장소로 통하는 네트워크 구간의 레이턴시(ping) 및 대역폭(Bandwidth)을 진단합니다.
* **작동 메커니즘**:
  * 에이전트가 정기적으로 백그라운드에서 지연 시간과 경량 다운로드 속도 측정 스크립트를 돌려 대시보드에 구간별 통계(P99 Latency 등)를 차트로 그립니다.
* **기대 효과**: AI 클라이언트가 제출한 작업이 평소보다 늦게 응답할 때, 모델 자체의 지연인지 특정 워커 노드의 네트워크 품질 저하 때문인지 신속히 파악합니다.

### 2.5 하드웨어 헬스 상태 및 디스크 SMART 모니터링
* **기능**: 가상 머신(VM)이 아닌 물리 서버(Bare-metal) 인프라를 운용할 때, 물리 디스크 및 팬 하드웨어 고장 전조를 모니터링합니다.
* **작동 메커니즘**:
  * `smartctl` 명령어를 사용해 NVMe/SSD의 예상 수명률(Wear-out Indicator) 및 디스크 배드섹터 증식을 감시합니다.
  * 하드웨어 RAID 컨트롤러의 상태와 CPU 온도를 수집합니다.
* **기대 효과**: 연산용 서버의 디스크나 메인보드가 갑자기 완전히 정지하기 전에, 이상 지표를 감지하여 가동 중단(Down-time) 없이 정상 노드로 작업을 안전히 사전 마이그레이션합니다.

## 3. 도입 우선순위 추천

1. **1단계 (보안 최우선)**: **사용자 SSH 키 및 계정 제어** + **방화벽 모니터링** (보안 외부 노출 통제)
2. **2단계 (인프라 안정화)**: **설정 파일 무결성 드리프트 감지** (설정 오염 방지)
3. **3단계 (성능 최적화)**: **네트워크 레이턴시 측정 및 하드웨어 헬스체크** (원인 진단 및 유지보수 예방)
