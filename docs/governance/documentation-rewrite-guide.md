# 문서 재작성 및 정본 관리 가이드

이 문서는 [문서 관리 정책](documentation-policy.md)을 기존 문서에 적용하는 절차와 완료 검사를
정의한다. 정책의 책임·메타데이터 규칙을 재정의하지 않는다. 이 가이드는 목표 상태를 정의하며,
현재 저장소가 모든 항목을 이미 충족한다는 선언은 아니다.

## 1. 범위와 진입점 확인

재작성 전에 대상 문서가 답할 독자 질문과 기능상 책임을 한 문장으로 적는다. 같은 책임을 가진
문서를 찾고 우선할 정본을 결정한다.

문서가 있는 기능 도메인은 `README.md` 또는 `index.md`를 진입점으로 둔다. 진입점에는 다음만 둔다.

- 도메인이 답하는 질문과 범위 밖 내용
- 권장 읽기 순서
- 파일별 책임, authority, 구현·검증 상태
- 인접 도메인의 정본 링크

`docs/assets/` 같은 자산 컨테이너는 기능 도메인 진입점 의무의 예외다. 호환성 때문에 남겨야 하는
legacy 경로는 소유자, 제거 조건과 대체 경로를 진입점이나 roadmap에 명시한다. 설명할 문서도,
호환성 책임도 없는 빈 디렉터리는 제거한다.

루트 `docs/index.md`는 도메인 탐색을 위한 카탈로그로 관리한다. 세부 파일 목록은 각 도메인
진입점이 소유한다. 기존의 세부 문서 행은 도메인 진입점으로 이관하는 과정에서 정리하며, 새로운
세부 문서를 루트 색인에 관성적으로 추가하지 않는다.

## 2. 내용을 책임별로 분류

| 문서 종류 | 담당하는 내용 | 두지 않는 내용 |
|---|---|---|
| Canonical contract/policy | 현재 결정, 불변식, 인터페이스·상태·권한과 실패 의미 | 대안 비교, 회의 기록, 운영 명령 |
| Derived reference | 정본의 요약, 코드 구조, 테스트·관측 근거와 구현 제약 | 새 정책 또는 계약 |
| Runbook | 준비, 실행 단계, 검증, 운영 롤백과 장애 대응 | 설계 배경의 재서술 |
| Proposal | 미승인·미구현 선택지, 위험, 승인·완료 조건 | 현재 지원되는 절차처럼 보이는 표현 |

정상·오류·복구가 같은 운영 작업을 완료하는 절차라면 한 Runbook에 둔다. 설계 정본은 실패의
의미와 안전 불변식을 정의하고, Runbook은 운영자가 수행할 복구 단계와 롤백을 정의한다. API 계약,
운영 절차, UI 설계와 보안 정책처럼 독자·승인자·변경 주기가 다른 내용은 분리한다.

## 3. 현재 사실과 목표 분리

보안, enrollment, 인증, lifecycle처럼 구현 전환 위험이 큰 문서는 현재 사실과 목표 계약을 표나
별도 절로 나눈다.

- endpoint, 권한, token·secret 전달, 기본값과 실패 순서를 코드·테스트·설정으로 대조한다.
- 조합에 따라 달라지는 인증·권한·재시도·소모 순서는 행렬 또는 상태 흐름으로 쓴다.
- 현재 사실에는 근거를, 목표에는 `proposed` 또는 `partial` 상태와 완료 게이트를 붙인다.
- 원문 secret, 실제 token, password와 query parameter credential은 기록하지 않는다.
- historical 또는 derived 문서의 실행 지침이 현재 정본과 충돌하면 필요한 사실만 정본에 반영한
  뒤 review로 이관하거나 삭제한다.

## 4. 논의·감사와 폐기 처리

비교, 감사, 대안과 논의 과정은 `docs/reviews/`에 둔다. 정본에는 확정된 결과만 짧게 반영한다.
review는 대상 정본, 검토 시점, 근거, 결정 결과, 정본 반영 링크와 남은 항목을 기록한다.

폐기 문서는 다음 순서로 처리한다.

1. 대체 정본 또는 대체 없음과 제거 책임자를 확정한다.
2. 파일명·표시명·링크·색인 행·예제 명령·자산 참조를 검색한다.
3. 필요한 비교 근거만 review로 보존한다.
4. inbound link와 진입점·루트 색인을 갱신한다.
5. 파일과 책임 없는 빈 디렉터리를 제거하고 `docs/log.md`에 이유와 대체 경로를 기록한다.

## 5. 재작성 절차

```mermaid
flowchart LR
    Scope["독자 질문과 도메인 확인"] --> Classify["현재 사실·목표·절차 분류"]
    Classify --> Verify["코드·테스트·설정 대조"]
    Verify --> Canonical["정본 선택과 중복 링크화"]
    Canonical --> Cleanup["폐기 파일·경로 정리"]
    Cleanup --> Review["비교 근거를 reviews에 보존"]
    Review --> Validate["진입점·링크·메타데이터 검증"]
```

임시 조사와 초안은 `.tmp/`에만 두고 최종 문서나 Git 기록에 포함하지 않는다.

## 6. 완료 게이트

문서 수정은 다음 항목을 확인한 시점에 내용상 완료다.

- [ ] 문서의 독자 질문과 기능상 책임이 하나로 설명된다.
- [ ] 도메인 진입점이 범위, 읽기 순서와 파일별 책임을 설명한다.
- [ ] 정본과 derived 관계가 하나로 결정되고 중복 계약은 링크로 교체됐다.
- [ ] 현재 사실·목표·미구현 상태가 분리되고 중요한 보안 경로는 근거와 대조됐다.
- [ ] Canonical은 실패 의미와 불변식, Runbook은 실행·복구 단계만 소유한다.
- [ ] 비교·감사·논의 기록은 `docs/reviews/`에 분리됐다.
- [ ] 폐기 문서는 inbound link와 자산 참조를 정리한 뒤 제거됐다.
- [ ] frontmatter가 [정책의 메타데이터 규칙](documentation-policy.md#4-메타데이터)을 따른다.
- [ ] 상대 링크, 삭제 경로, Mermaid 문법과 Markdown 형식 검사를 통과했다.
- [ ] 필요한 도메인 진입점, `docs/index.md`, `docs/log.md`가 갱신됐다.

Git 기록은 내용 검증과 별도 단계다. 사용자가 요청했거나 해당 작업 흐름에서 커밋 권한이 명시된
경우 변경 범위를 확인한 뒤 `docs:` Conventional Commit으로 기록한다. 문서 커밋은 가능한 한 코드
변경과 분리한다.
